# Repository Guidelines

## Project Structure & Module Organization
```
├── src/                    # Primary source code
│   ├── components/        # Reusable UI components
│   ├── modules/          # Feature-based modules
│   ├── utils/            # Shared utilities
│   └── index.ts          # Main entry point
├── tests/                # Test suites
│   ├── unit/            # Unit tests
│   ├── integration/     # Integration tests
│   └── fixtures/        # Test data
├── public/              # Static assets (images, fonts)
├── docs/                # Additional documentation
├── .bailucode.md        # This file
└── package.json         # Dependencies & scripts
```

## Build, Test, and Development Commands
| Command | Description |
|---------|-------------|
| `npm install` | Install dependencies |
| `npm run dev` | Start local development server (hot reload) |
| `npm run build` | Create production build in `dist/` |
| `npm test` | Run all tests once |
| `npm run test:watch` | Run tests in watch mode |
| `npm run lint` | Run linter (ESLint/Prettier) |
| `npm run lint:fix` | Auto-fix linting issues |

## Coding Style & Naming Conventions
- **Indentation**: 2 spaces (no tabs)
- **Language**: TypeScript preferred for new code
- **Naming**:
  - `camelCase` for variables/functions
  - `PascalCase` for classes/components
  - `kebab-case` for file names (e.g., `user-profile.tsx`)
  - `UPPER_SNAKE_CASE` for constants
- **Formatting**: Use Prettier with default settings. Run `npm run lint:fix` before committing.
- **Imports**: Group in order: 1) Node modules, 2) Third-party, 3) Internal. Use absolute paths from `src/`.

## Testing Guidelines
- **Framework**: Jest + React Testing Library (for UI)
- **Location**: Tests co-located with source (`Component.test.tsx`) or in `tests/unit/`
- **Coverage**: Minimum 80% for new code. Check with `npm test -- --coverage`
- **Naming**: `*.test.ts` or `*.spec.ts` for unit tests
- **Write tests for**:
  - All public functions/components
  - Edge cases and error states
  - User interactions (click, input)

## Commit & Pull Request Guidelines
- **Commit Messages**: Use [Conventional Commits](https://www.conventionalcommits.org/):
  ```
  feat: add user authentication flow
  fix: resolve memory leak in data fetcher
  chore: update dependencies
  ```
- **Pull Requests**:
  - Link to related issue (e.g., `Closes #123`)
  - Include description of changes and testing steps
  - Add screenshots for UI changes
  - Ensure CI passes (tests, lint, build)
  - Request review from at least one team member

## Architecture Overview
- **State Management**: Use React Context or Redux Toolkit for global state. Keep local state local.
- **API Layer**: All API calls in `src/services/`. Use Axios with interceptors for auth/errors.
- **Routing**: File-based routing (if using Next.js) or centralized router config.

## Security & Configuration Tips
- **Never commit** `.env` files. Use `.env.example` as template.
- **Secrets**: Store in environment variables (`process.env.VAR_NAME`). Validate at runtime.
- **Dependencies**: Regularly audit with `npm audit`. Update promptly for security patches.
- **Input Validation**: Sanitize all user inputs on frontend and backend.

## Agent-Specific Instructions
- When generating code, follow existing patterns in `src/`.
- Prefer small, focused commits with clear messages.
- If adding new dependencies, justify in PR description.
- Update this document if project structure or conventions change.
